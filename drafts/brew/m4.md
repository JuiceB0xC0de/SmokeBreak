# m4

**TLDR;** The classic Unix macro processor: it copies text through and expands macros as it goes, and it quietly sits under GNU Autoconf.

m4 reads input, copies it to output, and expands macros when it meets them. Macros are either builtin or user-defined, and they can take any number of arguments. Builtins cover including files, running shell commands, integer arithmetic, and text manipulation. It can sit in front of a compiler or be used as a macro processor on its own.

GNU M4 is the GNU implementation of the traditional Unix tool. It is mostly SVR4 compatible, with extensions such as handling more than 9 positional parameters. The project page notes that "One of the biggest users of GNU M4 is the GNU Autoconf project." Many people have run m4 indirectly through `configure` scripts without ever typing the command.

The idea underneath is a language that works purely by rewriting text. There is no separate syntax tree to build, just input that gets expanded, and the output can be fed back in. Once macros can define macros, do arithmetic, and call the shell, a text substituter becomes a small programming language. That is why it is a door into how generated build systems and templating work.

The homepage gives no usage examples, so the manual is where to learn how macros are written. A 2.0 version is described as planned, with better input control, multiple precision arithmetic, and loadable modules. Those are future plans, not current features.

## Install

```
brew install m4
```

## Try this

```
m4 --help
```
Lists the command-line options for the macro processor.

```
info m4
```
Opens the GNU M4 manual locally, which is where the macro examples live.

## What's unique

It is the macro engine behind GNU Autoconf, and it has shell execution, arithmetic, and file inclusion built into a plain text-rewriting language.

## Caveats

The homepage shows no macro examples, and the 2.0 features it lists are plans rather than shipped; the stable release is 1.4.20.
