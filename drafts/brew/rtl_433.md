# rtl_433

**TLDR;** Decodes the radio chatter of weather stations, doorbells, tyre sensors and meters around you, using a cheap USB radio dongle and one command.

rtl_433 is a command-line receiver for the license-free ISM bands, mainly 433.92 MHz, plus 868, 915, 315 and 345 MHz. It reads samples from a software-defined radio, either an RTL-SDR dongle or something like a HackRF, LimeSDR or PlutoSDR through SoapySDR, or from a saved sample file. It turns the signal into pulses and tries each one against several hundred per-device decoders. Matches print as text, JSON, CSV, MQTT, InfluxDB or syslog, or are served through an HTTP UI.

The README calls it "a generic data receiver" and says that, despite the name, it is not tied to RTL-SDR hardware or to one kind of device. Its stated goals are low resource use and few dependencies, so it can run on embedded hardware.

The idea underneath is that a lot of cheap wireless gear shouts unencrypted data into the air with simple modulation: temperature readings, remote button presses, tyre pressures, meter readings. Once you can see the pulses, you can learn how those devices talk. The pulse analyzer (-A) summarises pulse, gap and period timings. The flex decoder (-X) lets you describe an unknown OOK or FSK device in a single command-line string, with no C required.

The README is blunt about trust: "The output is literally pulled from thin air, it's not to be trusted." Anyone with a transmitter can produce messages, so keep it on a trusted local network.

## Install

```
brew install rtl_433
# Needs hardware: an RTL-SDR USB dongle (or a SoapySDR-supported radio such as HackRF, LimeSDR or PlutoSDR) and an antenna.
# On Linux, if the kernel DVB driver claims the dongle, blacklist dvb_usb_rtl28xxu or unload it with rmmod.
```

## Try this

```
rtl_433 -h
```
Prints the full usage help, including the numbered list of supported device protocols.

```
rtl_433 -C si
```
Listens on the default band and prints decoded messages from nearby devices, with units converted to metric.

```
rtl_433 -A
```
Turns on the pulse analyzer, which summarises pulse, gap and period timings and attempts a decode of signals it cannot name.

## What's unique

The protocol list is very long, with many entries naming exact brands and models, and the flex decoder lets you describe a new device without writing code. Output options cover MQTT, InfluxDB, syslog and a built-in HTTP UI.

## Caveats

It needs an SDR dongle, Linux users may hit a kernel driver conflict, some decoders are off by default, and the README says not to trust the output.
