# s6

**TLDR;** A small toolbox of independent Unix programs for supervising services, descended from daemontools and runit, built to be assembled rather than used as one big init.

s6 is a suite of command-line programs for process supervision: starting a long-running service, watching it, restarting it when it dies, logging its output, and telling other things when it is ready. It follows daemontools and runit. Two long-lived processes, `s6-svscan` and `s6-supervise`, hold the supervision tree up. The other programs control them and report service state.

The interesting part is how the pieces are cut. The tools are independent and work inside or outside the supervision framework. The homepage lists some of what they can be combined into: syslogd-style logging with `s6-log`, readiness notification that serves as the basis for dependency management, sudo-like privilege gain without setuid binaries (`s6-sudo`), and socket-activation-like behaviour without changing the application. `s6-fdholderd` is the fd-holding piece of that last idea.

The author describes it as a toolbox for low-level process and service administration, meant to do a lot with very little code. The homepage argues that all-in-one init systems feel complex and convoluted, and that people who meet the supervision approach usually find it much simpler. Reading that section, and the opinionated page on other init systems, is a good way into the design argument.

The programs also share conventions. Exit codes are documented: 111 for a temporary error, 100 for a permanent one, 127 if the program to exec is not found, and 126 if exec fails for another reason. That makes the tools easy to chain in scripts.

## Install

```
brew install s6
# The homepage does not mention Homebrew; it describes building from source. Needs a POSIX system with a C toolchain and GNU make 3.81+, plus skalibs, and optionally execline (both are formula dependencies).
# Source: git clone git://git.skarnet.org/s6, then follow the INSTALL file.
```

## Try this

```
git clone git://git.skarnet.org/s6
```
Fetches the source if you want to build it yourself; the homepage says to follow the INSTALL file.

```
s6-svscan --help
```
Prints usage for the program that scans a service directory and keeps a supervisor running for each service.

```
s6-log --help
```
Shows usage for s6's logger, the piece that handles service output and log rotation.

## What's unique

It splits supervision, logging, readiness notification, fd-holding and privilege gain into separate small tools you compose yourself. It is not a single init, and the author argues that is the point.

## Caveats

The brief found no release date or last-commit date, and s6 on its own is a supervision suite rather than an init; init replacement lives in separate projects (s6-linux-init, s6-rc, s6-overlay).
