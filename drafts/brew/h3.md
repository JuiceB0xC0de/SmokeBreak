# h3

**TLDR;** Uber's hexagonal geospatial index: turn a latitude and longitude into a short hex cell ID, then ask for that hexagon's corners or center.

H3 is a C library that divides the globe into hexagons. You give it a coordinate and a resolution from 0 (coarsest) to 15 (finest), and it returns a 64-bit cell ID, written as a hex string like `8a2a1072b59ffff`. Given a cell ID, it can hand back the hexagon's boundary vertices or its center point.

It was built at Uber so data from different sources could be joined on a shared grid and aggregated at different levels of precision. The homepage says the grid enables algorithms such as nearest neighbors, shortest path, and gradient smoothing. The README describes it as combining the benefits of a hexagonal grid with the hierarchical subdivisions of Google's S2 library.

The idea underneath is the awkward part. Hexagons do not nest neatly inside bigger hexagons the way squares do, so H3 only subdivides them approximately. Each cell ID encodes its place in the hierarchy, and you trade perfect containment for a grid where every neighbor is about the same distance away. The README does not go into the projection or indexing math, so the command-line tools are a way to poke at the behavior before reading further.

The Homebrew package installs small command-line wrappers around the C API. They let you convert a point to a cell and a cell back to geometry from a shell, with no code to write.

## Install

```
brew install h3
# Building from source instead needs a C compiler (gcc or clang), CMake, and Make. No accounts or API keys.
```

## Try this

```
latLngToCell --resolution 10 --latitude 40.689167 --longitude -74.044444
```
Prints the H3 cell index for the Statue of Liberty at resolution 10. The README shows it as 8a2a1072b59ffff.

```
cellToBoundary --index 8a2a1072b59ffff
```
Prints the six corner vertices of that hexagon as latitude/longitude pairs.

```
cellToLatLng --index 8a2a1072b59ffff
```
Prints the hexagon's center coordinate, around 40.689, -74.044.

## What's unique

It is a hexagonal grid with a hierarchy, and it openly accepts that subdivision across scales is only approximate. It also ships small shell tools so you can inspect cells without writing code.

## Caveats

The homepage is thin marketing copy, and the README does not explain the extra tools like gridDisk or cellToLocalIj, so expect to read the documentation site for those.
