# sequin

**TLDR;** Pipe any program's coloured output into sequin and it names every ANSI escape sequence and says what it does, a quick look at how terminals are told what to draw.

Sequin is a small filter from Charm. It reads text containing ANSI/VT escape sequences on stdin and prints a plain description of each one: which colour is being set, what is switched on or off, where the cursor moves. With `-r` it keeps the original text and highlights the sequences inline instead. With `sequin -- <command>` it runs the program for you in a fake TTY, so the program behaves as if it were talking to a real terminal.

The README pitches it as a debugging tool for CLIs and TUIs, for describing escape sequences you don't understand, and for exploring what TUIs do under the hood. It also mentions inspecting golden files generated by Bubble Tea's teatest.

The idea underneath is that a terminal is not a canvas. Everything a program does to it, from bold text to colour to cursor movement, travels as ordinary bytes in the same stream as the text, marked off by an escape character. Most people never see those bytes because the terminal swallows them. Sequin makes them visible and gives them names. It builds on the `ansi` package from Charm's `x` project, which is where the parsing lives.

It is a learning tool as much as a debugger. Run `ls` or `git status` through it and you see what your everyday tools say to your terminal all day.

## Install

```
brew install sequin
```

## Try this

```
printf "\x1b[38;5;4mCiao, \x1b[1;7mBaby.\x1b[0m\n" | sequin
```
Sends a short string with colour, bold and reverse-video codes into sequin, which explains each sequence.

```
git -c status.color=always status -sb | sequin
```
Shows the escape sequences git emits for its coloured status output, described one by one.

```
git -c status.color=always status -sb | sequin -r && echo
```
Prints the original text with the escape sequences highlighted inline instead of described separately.

## What's unique

It names each sequence and explains its effect rather than just stripping or dumping the bytes. The fake-TTY mode lets you inspect a program's real output without setting anything up.

## Caveats

The README says it is unfinished: common sequences are covered but APC sequences are not yet supported, and many programs drop colour when piped unless you force it.
